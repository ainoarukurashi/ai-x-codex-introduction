Windows版で困った時

エラー画面を見ながら、落ち着いて確認しましょう

Codexの初回起動やアップデート直後は、Windowsの権限・セキュリティ設定・Storeの状態によって止まることがあります。 まずはエラー画面をスクリーンショットで残し、下の再現画像に近いものを探してください。

症状から探す Windowsセットアップへ戻る

最初にやること

いきなり難しい設定を触らなくて大丈夫です

まずは安全な確認から進めます。会社や学校のPCでは、管理者権限が必要な場合があります。

1

エラー画面を撮る

画面全体のスクリーンショットを残します。文字が読める状態だと確認しやすいです。

2

Codexを再起動する

一度閉じてから、もう一度Codexを開きます。更新直後の一時的な不具合なら直ることがあります。

3

PCを再起動する

Windows UpdateやStore更新が残っている場合、PC再起動で状態が整うことがあります。

4

まだ直らなければ共有

下の「共有するもの」をそろえて、講座前に相談してください。

ケース1

サンドボックス関連エラー

「workspace dependency repair」「sandbox setup failed」のような表示が出る場合です。

見分けるポイント

Codexが作業用の安全な環境を準備できず、依存関係の修復やサンドボックス作成で止まっている状態です。

考えられる原因

  • Microsoft Visual C++ Redistributableが入っていない
  • Visual Studio Build ToolsのC++関連機能が不足している
  • Windowsの権限やセキュリティ設定で止まっている
  • Windows 10で一部機能がうまく動かない

対処の順番

  1. Codexを閉じて、PCを再起動します。
  2. Microsoft Visual C++ Redistributable (x64) をインストールします。
  3. 必要に応じてVisual Studio Build ToolsのC++ワークロードを入れます。
  4. Codexの設定でSandboxモードを切り替えられる場合は、別のモードで試します。

設定ファイルを直接編集する場合、Windowsでは C:\Users\ユーザー名\.codex\config.toml を扱います。 初心者の方は無理に編集せず、まずスクリーンショットを共有してください。

ケース2

起動時に「Codex failed to start」と出る

.codex フォルダを作れない、または読み書きできない時に起きることがあります。

見分けるポイント

EPERM: operation not permitted や .codex\sqlite のような文字が表示されます。

考えられる原因

  • ユーザー名に日本語や特殊文字が含まれている
  • .codex フォルダへの権限が足りない
  • 企業管理PCの制限がある
  • アンチウイルスやセキュリティソフトが止めている

対処の順番

  1. Codexを右クリックして「管理者として実行」を試します。
  2. %USERPROFILE%\.codex を .codex_backup などに名前変更してから再起動します。
  3. 会社や学校のPCなら、管理者にアプリ利用の許可を確認します。
  4. 特殊文字が原因らしい場合は、新しいWindowsユーザーで試す方法もあります。

.codex フォルダを削除・リネームする前に、必要そうなファイルがないかだけ確認してください。 不安な場合はスクリーンショットを共有してから進めましょう。

ケース3

Microsoft Storeの「不明なエラー」

インストール前に止まる場合は、CodexではなくStore側の状態が原因のことがあります。

見分けるポイント

Store画面で「Unknown Error」「Something happened on our end」のように表示され、インストールが始まりません。

考えられる原因

  • Microsoft Storeのキャッシュが壊れている
  • Windows Updateが残っている
  • ネットワークが一時的に不安定
  • Microsoft Store側の一時的な不具合

対処の順番

  1. Storeアプリを閉じて、もう一度開きます。
  2. Windows Updateを確認し、必要ならPCを再起動します。
  3. wsreset.exe を実行してStoreのキャッシュをクリアします。
  4. 時間を置いて、公式ダウンロードページからもう一度試します。

ケース4

権限・Firewall・WindowsApps関連のエラー

Windowsの保護機能や会社PCの制限で、Codexの動作が止まることがあります。

見分けるポイント

WindowsApps、Access denied、Firewall、ACL のような文字が出る場合です。

考えられる原因

  • WindowsAppsフォルダへのアクセス制限
  • Firewallやセキュリティソフトによる通信ブロック
  • 管理者権限が必要なPC設定
  • アップデート直後に設定がずれた

対処の順番

  1. Codexを再起動し、必要ならPCも再起動します。
  2. Windows セキュリティやFirewallでCodexがブロックされていないか確認します。
  3. Codexを一度アンインストールし、再インストールします。
  4. 会社PCの場合は、管理者にアプリ利用と通信許可を確認してください。

補足

アップデート後・CLI併用時の注意

講座ではCodexデスクトップアプリを使うため、CLIのセットアップは必須ではありません。

更新後

更新直後に壊れたように見える

Codexのアップデート直後に起動しない場合は、Codexを閉じてPCを再起動します。 それでも直らない時は、%USERPROFILE%\.codex をバックアップ名に変更してから再起動すると改善することがあります。

CLI

CLIを使っている人だけ

npm install -g @openai/codex でPermissionエラーが出る場合は、PowerShellの管理者実行やPATH設定が関係します。 今回の講座ではCLIは使わないため、無理に進めなくて大丈夫です。

講座前に共有するもの

ここまで分かれば十分です

  • Windowsのバージョン（Windows 10 / Windows 11）
  • エラー画面のスクリーンショット
  • 止まった手順（インストール / サインイン / フォルダ選択 / 起動時など）
  • 表示されたエラーメッセージ
  • 会社PC・学校PCか、自分のPCか

大事なこと

分からなくても止まらなくて大丈夫

ここに出てくる言葉は少し難しく見えますが、受講者の方が全部理解する必要はありません。 エラー画面を残しておけば、どこで止まっているかを一緒に確認できます。
